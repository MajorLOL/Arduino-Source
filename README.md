# PocketPilot Studio

<img src="IconResource/pocketpilot.png" width="96" alt="PocketPilot Studio's icon: a handheld console with a play arrow on its screen">

Automation programs for Switch games: run them, and build or fix them with Claude.

A program of PocketPilot Studio plays a Pokémon game on a Nintendo Switch by itself. It watches the game through a capture card and presses the buttons through a controller board (for example an ESP32). Claude, in a panel of the main window, answers questions about the programs and can change their source: on a branch of its own, which becomes a pull request.

It is a personal fork of [Pokémon Automation](https://github.com/PokemonAutomation/Arduino-Source)'s "SerialPrograms", with a new interface, a program that plays the whole story of FireRed and LeafGreen, Claude built in, and fixes of its own. The programs for the other games are those of Pokémon Automation. Until build 12 its name was PocketPilot; the files and folders of the builds still have that name.

PocketPilot Studio is not made, endorsed or supported by Nintendo, Game Freak, Creatures or The Pokémon Company, nor by Anthropic or the Pokémon Automation project. Please do not ask the Pokémon Automation team for help with this fork: use the [issues of this repository](https://github.com/MajorLOL/Arduino-Source/issues).

## Getting it

Every push to the branch `pocketpilot` makes a Windows build and tests that it starts. A build that passes is published: the [releases](https://github.com/MajorLOL/Arduino-Source/releases) named "PocketPilot Studio - Windows build N" ("PocketPilot - Windows build N" until build 12). Unzip `PocketPilot-Windows.zip` and run `SerialPrograms.exe`. Each release also has pictures of that build's interface, taken on the build machine.

To keep your settings, close the old program first, then copy its `UserSettings` folder into the new folder. (The program writes its settings when its window closes. Since build 38 the AutoStory also has them written at its start and at each save of the game, so a copy made while it is still open has the options of the run.)

The hardware and its setup are the same as for Pokémon Automation: see [its documentation](https://pokemonautomation.github.io/).

## Building

PocketPilot Studio builds like Pokémon Automation's SerialPrograms: see [SerialPrograms/BuildInstructions](SerialPrograms/BuildInstructions). The Windows builds are made by [this workflow](.github/workflows/pocketpilot-windows.yml) with Qt 6.10.2.

`SerialPrograms --ui-screenshots <folder>` starts the program, saves a picture of each page, theme and opened list in the folder (then makes the window as the screens of the setup, goes from the games to a program, the settings and Claude and back, and saves a picture of each in its subfolder `app`) and exits (nothing is pressed on a console, no setting is saved). It also holds a conversation with a made-up Claude that ends in a commit on a made-up GitHub: no key is used and nothing is sent anywhere. Its exit code is 0 when every picture was taken and every check passed.

## Language and setup

The intro and the setup are one screen: the film plays on the window of the setup, its last picture fades into the first question, and when the setup is over the screen stays up until the main window is there, so that nothing opens or closes in between and the desktop never shows. After the intro, the first start asks three things, full screen and in the style of the intro: the **language**, the **console** and the **microcontroller**, and ends with the choice of the **game** to start. Only the intro is a film; the rest are menus that wait for your choice (mouse or keyboard: arrows, Enter, Tab, Esc). Both can be opened again in Settings ("Open the setup").

- **Language.** English is the default. Dutch, German, French and Spanish come with the program; **Other** reads a file of your own, `Languages/custom.json` next to the program. The language applies at once, also to the windows that are open, and can be changed in Settings ("Language").
- **Console.** After the language comes a screen of its own, in the same style, with the consoles that the program supports now as two large tiles: **Nintendo Switch** (Switch 1 and the OLED model) and **Nintendo Switch 2** (the international and the Japan-only models, as the program lists them). Under them the consoles that come later are already on the screen, dimmed and with a dashed outline, under "Coming soon": PlayStation 5, 4, 3, 2, the first PlayStation and Classic, Xbox Series X|S, One, 360 and the original Xbox, Wii U, GameCube, Nintendo 64 and Dreamcast (the platforms that community gamepad adapters such as OGX-Mini speak, and what the commercial ones list). They cannot be picked yet; the arrows and Tab skip them. Pick one of the two with the mouse, or with the arrows and Enter, and press Continue: the question of the microcontroller follows, which is the setup itself. To add a console, see the comment above `CONSOLES` in `PocketPilot_Setup.cpp`. The choice is kept in Settings ("Console") and shown as picked when the setup is opened again. For now it is only kept: the programs still detect the console themselves. "Skip setup" skips it, like the rest of the setup.
- **Microcontroller.** Raspberry Pi Pico W, Pico 2 W, ESP32 and ESP32-S3 get their seven steps in the program, and the installation can be done from the menu: the program lists the serial ports of the computer (it knows the CP210x and CH340 chips and offers their drivers and the Device Manager), puts the firmware on a Pico that is in flash mode (it finds the drive `RPI-RP2` or `RP2350`, copies the file and waits for the Pico to restart), and flashes an ESP32 with esptool, showing the progress. The AVR8 boards (Leonardo, Uno R3, Pro Micro, Teensy) are shown as not supported, because that support was discontinued. **Other** opens the **Setup Guide** inside the program, in the same style, with the boards and what you need; the guides that are not in the program open in your browser. The steps are those of the [Pokémon Automation Setup Guide](https://pokemonautomation.github.io/SetupGuide/index.html); check there for anything newer.
- **Firmware.** The firmware that comes with the build is in the folder `Firmware`; the list of versions also shows the newer ones that are online (Pokémon Automation's [Packages](https://github.com/PokemonAutomation/Packages/tree/master/Firmware)) and can download one into that folder. Each version has its **download link** on the screen, with buttons to open it, copy it and open the Firmware folder. The program checks that a file is a firmware file of the board before it is used. What the program cannot do for you is the last part: picking `Serial: PABotBase2`, the port and the type in the program of the game (those settings belong to each program), which the steps show as what to pick.
- **Which game to start.** The installation ends with "You are done!". After it, as a new screen of its own that is no part of the installation (no steps at the top, no way back into it), comes the choice of the game, in the same style: the games of the program as cartridges (the same ones as on the Games page, each with the game's own logo, large and on its own background, and the number of programs). Pick one with the mouse, or with the arrows and Enter, and press Start: the program opens with that game and its programs. "Choose later" leaves the choice to the Games page. The link "Choose another console" at the bottom goes back to the choice of the console (the one chosen before is picked): Continue leads to the games again, without asking for the board once more, and "Back to the games" there leaves it as it was. The screen also comes at every start, after the intro (and after the setup, at the first start), so that you can pick the game before the main window opens; turn that off in Settings with "Ask which game to start at every start", or start the program with `--no-language-prompt`. The choice is also asked when the setup is opened from Settings, which then shows the game in the window that is open. "Skip setup" does not skip it: after a skip the choice of a game comes as well.
- **Which program to start.** When the game that was picked has programs, a screen of its own follows, in the same style, with the setup's background behind it. At the left, the programs of the game (for the Nintendo Switch only its "Programs"), with a search field (just type), the tag of each program (beta, rough, ...) and, under the list, its name and description. In the middle, the live picture of the first capture card the program finds (a list under the picture lets you pick another one; the choice is remembered), with checks for Video, Audio, Board and Keys, and the loudness of the sound. At the right, the output log of the program with filters (All, Info, Warn, Error) and three buttons: **Copy for Claude** (a text with the build, the computer, the devices, the program that is picked and the log, ready to paste into Claude to find out what is wrong), **Copy log** (the lines that are shown) and **Save .txt** (the same text as Copy for Claude, in the folder Debug next to the program). Under it, a timeline of the last minute with a lane each for the picture (pictures per second), the sound, the board, the log and the keys of the window; drag over it to select a range, and Copy for Claude copies the log of that range. The lane of the program stays empty until a program runs. Pick a program and its **options** slide open in a panel right next to the list (the picture, the checks, the log and the timeline get narrower to make room): they are the options of the program's own page, so what is changed there is what the page shows later, and it is kept a moment after the change. A program with many options (twelve or more things to set, as the AutoStory has) opens the panel wide, over the picture, the log and the timeline; the button with the two arrows at the top of the panel makes it wide or narrow, and what is chosen stays for the other programs. The button in the corner of the picture, or F11, puts the picture over the whole screen (the name of the card, "Live" and the size stay in its corners); Escape, Enter, F11 or the button in its corner bring the page back. Tab goes into the panel from its title, Escape gives the keyboard back, Escape again (or the cross) closes the panel. Up/Down, Home/End and the wheel go over the list, Enter starts the program (not while a field of the options has the keyboard), "All games" goes back to the games, "Choose later" opens the game without a program. Turn the screen off in Settings with "Ask which program to start after the game".
- **Video tutorials.** "Watch the video tutorial" on the steps plays a film of the setup (one for the Picos, one for the ESP32, one for the ESP32-S3). They are recorded from the real screens of the program in demo mode (nothing is flashed), with a cursor and captions, and play in the program.

**How the translation works.** The English text stays in the source. A language is a file, `Resources/lang/<code>.json`: the English text as the key, the translation as the value (`%1`, `%2` ... and tags are kept as they are; keys that start with `@` are comments; an empty value means "not translated yet"). Text that the program composes goes through `tr_ui("...")`; the labels, buttons, group boxes, tabs, menus, tool tips, placeholders and window titles of every window are translated by a filter on the application, so the files of Pokémon Automation's own options and panels did not have to change (merging its updates stays easy). Drop-down lists of the programs and the items of lists are left alone on purpose: the programs read their choice back from that text.

**What is translated, and what is not (yet).** The setup, PocketPilot's own windows (frame, Games page, About), the Global Settings and the notices and buttons of the program panels are translated. The option texts of the programs of the games (thousands of them) and the prompts of Claude are not: they stay English until they are added to a dictionary. A text that has no translation stays English and never breaks anything. With a language other than English, the texts that were looked up and not found are written to `Languages/missing-<code>.json` when the program closes, as a list to start from. To add or fix a translation without building the program, put a file `Languages/<code>.json` (for example `nl.json`) next to the program: what is in it wins over the built-in file.

`SerialPrograms --language-test` loads every language, checks that each translation keeps what must not change (`%1`, tags, line breaks) and that every language has the same texts, and translates a few windows. `SerialPrograms --setup-test <folder>` goes through the setup with clicks and keys, saves a picture of each screen in the folder and checks what was answered. `SerialPrograms --tutorial-test` decodes the three tutorial films without a window. The Windows workflow runs all three; the pictures go with the build.

## Where the code is

PocketPilot Studio's own code is in [SerialPrograms/Source/PocketPilot](SerialPrograms/Source/PocketPilot): the themes, the frame of the main window, the Games page, the look of the program list, the "About" window and the test of the interface. Claude is in its folder [Assistant](SerialPrograms/Source/PocketPilot/Assistant): the connection to the Claude API, the conversation and its tools, the work on the repository through GitHub, and the panel. The rest of the tree is Pokémon Automation's, with the changes this fork needs. The branch follows Pokémon Automation's `main` by merging it.
